## Results

<Accordions>
  <Accordion title="No streams, or fewer than you expected">
    If an addon finds a stream on its own but it's missing in AIOStreams, a filter almost always removed it. Statistic streams show which one:

    <Steps>
      <Step>
        Go to **Miscellaneous → Display → Statistic Streams** (switch the
        interface to **Advanced** on the **About** page if you don't see it).
      </Step>
      <Step>
        Turn it on and select `filter` under **Statistics to Show**. **Show
        Filter Stats on No Streams** adds them when nothing is left.
      </Step>
      <Step>
        Search again. Extra streams at the top or bottom of the list show how
        many results each filter removed, and how each addon did.
      </Step>
    </Steps>

    Common causes:

    - **Required languages.** Most filenames don't name their language, so requiring English removes most results. Prefer a language instead of requiring it.
    - **Excluded stream types.** ElfHosted's public instance always removes P2P, HTTP and Live streams.
    - **The Digital Release Filter** (under **Filters → Miscellaneous**) removes results for films not yet released digitally, so a new film can show nothing until its digital release.
    - **A template's own filters.** Tamtaro's setup keeps a set number of the best streams for each resolution: raise the SELect Engine numbers in its options if you want more.
    - **An addon that failed.** The statistics show addons that errored or timed out; see [Failed to fetch manifest](#errors) below.

  </Accordion>

  <Accordion title="Results for the wrong season, episode or film">
    The matching filters remove streams that don't match what you asked for:

    <Steps>
      <Step>Go to **Filters → Matching**.</Step>
      <Step>
        Turn on **Title Matching**, and add a TMDB API key under **Services**
        if your instance doesn't provide one (free, see the [Setup
        Guide](/configuration/setup#step-3-get-a-tmdb-api-key)).
      </Step>
      <Step>Turn on **Season/Episode Matching** for shows.</Step>
      <Step>Optionally turn on **Year Matching** to drop remakes and reboots.</Step>
    </Steps>

    If the stream itself is mislabelled (its filename names the wrong episode), matching can't catch it.

  </Accordion>

  <Accordion title="Unwanted streams still show up">
    **Included** filters and passthrough expressions keep a stream even when another filter would remove it. If you included 1080p, an uncached 1080p stream stays even with **Exclude Uncached** on. Check the **Included** options in each filter, and **Included Stream Expressions** under **Filters → Stream Expression**.

  </Accordion>

  <Accordion title="Results are slow to appear">
    AIOStreams waits for every addon to answer, so the slowest one sets the pace. The statistic streams show each addon's response time.

    - Lower each addon's **Timeout** to the most you're willing to wait (5,000 ms suits most).
    - Remove addons you rarely need.
    - Use [Groups](/guides/groups) to ask backup addons only when the main ones come up short.

  </Accordion>
</Accordions>

## Errors

<Accordions>
  <Accordion title="'Failed to fetch manifest', or an addon errors or times out">
    The addon itself is down, slow or refusing your instance. AIOStreams can't save while an addon's manifest fails, so:

    1. Go to **Addons**, disable the addon named in the error, and save.
    2. Try it again later and re-enable it once it works.

    A `403 - Forbidden` means the addon blocked your instance's IP; Torrentio does this to most servers (see [Torrentio returns 403](#self-hosting)). A `429 Too Many Requests` means the addon is limiting how often your instance can ask; on a public instance, everyone shares the instance's IP, so another instance may work better.

  </Accordion>

  <Accordion title="'Failed to validate TMDB API Key'">
    Check the key under **Services → Metadata**. TMDB gives you two: the 32-character API Key goes in **TMDB API Key**, and the much longer Read Access Token in **TMDB Read Access Token**. A key in the wrong field fails. If the key is right and you self-host in India, see [TMDB calls fail in India](#self-hosting) below.

  </Accordion>

  <Accordion title="'You are only permitted to use specific regex patterns' or 'Forbidden regex'">
    Instances only accept regex patterns they trust. Templates such as Tamtaro's ship patterns the instance allows, and those change when the template updates, so the fix is usually to **run the template again** at its latest version.

    - **On a public instance:** if that doesn't help, ask the host to trust your patterns.
    - **Self-hosting:** add the template's URL to **Template URLs** in the dashboard's **Settings** (`TEMPLATE_URLS`), or set **Regex filter access** to `all` (`REGEX_FILTER_ACCESS`).

  </Accordion>

  <Accordion title="'Forbidden URL' when syncing Stream Expressions">
    Instances only sync Stream Expressions from URLs they allow.

    - **On a public instance:** ask the host to add the URL to `WHITELISTED_SEL_URLS`.
    - **Self-hosting:** set **SEL sync access** to `all` in the dashboard's **Settings** (`SEL_SYNC_ACCESS`).

  </Accordion>

  <Accordion title="A public instance is down">
    Use another [public instance](/getting-started/public-instances) in the meantime. Export your configuration when the instance is back (**Save & Install → Backups → Export**) so you can import it elsewhere next time.

  </Accordion>
</Accordions>

## The AIOStreams app and Jellyfin apps

<Accordions>
  <Accordion title="The home page is empty, or a title won't open">
    Your configuration has no catalog or metadata addon. The apps only show what your configuration provides: add AIOMetadata to AIOStreams, as in [step 7 of the Setup Guide](/configuration/setup#step-7-add-catalogs-and-metadata).

  </Accordion>

  <Accordion title="A video won't play, or has no sound, in a browser">
    AIOStreams never converts video, and browsers can't play many formats: MKV files, HEVC video, and DTS or TrueHD audio often fail. Use the [desktop](/apps/desktop) or [Android](/apps/android) app, which play nearly anything, or choose another player under **Settings → Playback → Player**.

  </Accordion>

  <Accordion title="Playback buffers">
    - **Your connection.** A 4K remux can need 60 Mbps or more, so leave room on top of the stream's bitrate, about a third. The bitrate shows in the version list when your format includes it. To keep big streams out, set a limit under **Filters → Bitrate**.
    - **Your device.** Some devices can't decode every format, Dolby Vision profile 5 in particular, and stutter instead of failing. Try another version of the title.
    - **The service.** Try a version from another service or addon, to see whether one source is slow.

  </Accordion>

  <Accordion title="Finished titles stay in Continue Watching">
    A title counts as played once you've watched 90% of it. Stop before that, for example at the start of the credits, and it stays in Continue Watching. Skip to the end before stopping, or choose **Mark watched** in its menu. Self-hosters can change the threshold with **Played percentage** in the dashboard's **Settings** (`WATCH_STATE_PLAYED_PERCENT`).

  </Accordion>

  <Accordion title="A Jellyfin app can't connect to my self-hosted instance">
    - **Use HTTPS.** Apps on iPhone, iPad and Apple TV often refuse plain HTTP addresses.
    - **Let the server's paths through any login in front of it.** Authelia, Pangolin and similar tools block apps that can't show a login page. Exempt `/jellyfin` (and `/stremio` for the Stremio addon).
    - Test it: open your sign-in address in a private browser window. If it asks for your proxy's login, so will the apps.

  </Accordion>
</Accordions>

## Self-hosting

<Accordions>
  <Accordion title="Stremio shows 'Failed to fetch' or refuses to connect">
    Stremio only accepts addons served over **HTTPS**.

    <Steps>
      <Step>
        Put a reverse proxy in front of AIOStreams. Traefik and Caddy can get
        certificates from Let's Encrypt automatically.
      </Step>
      <Step>
        The [Deployment guide](/getting-started/deployment) has a ready-made
        Docker Compose and Traefik setup.
      </Step>
      <Step>
        Check the certificate by opening `https://your-domain/stremio/manifest.json`
        in a browser. You should see JSON.
      </Step>
      <Step>Reinstall the addon in Stremio with the HTTPS address.</Step>
    </Steps>

    <Callout type="info">
      Stremio Web accepts plain HTTP for `localhost`, but Stremio's desktop and
      mobile apps need HTTPS for anything else.
    </Callout>

  </Accordion>

  <Accordion title="My configuration disappears after updating or recreating the container">
    AIOStreams' data folder isn't on a persistent volume, so the database goes with the container.

    <Steps>
      <Step>Stop the containers: `docker compose down`</Step>
      <Step>
        Map the data folder in `compose.yaml`, under the AIOStreams service:

        ```yaml
        volumes:
          - ./data:/app/data
        ```
      </Step>
      <Step>Start them again: `docker compose up -d`</Step>
    </Steps>

  </Accordion>

  <Accordion title="Torrentio returns 403 or won't install">
    Torrentio blocks many servers, including most VPS providers and many AIOStreams instances. A `403 - Forbidden` in the logs, or **Failed to fetch manifest for Torrentio**, means it blocked yours. Routing it through a VPN can work (see [Torrentio blocks](/getting-started/deployment#torrentio--stremfun-blocks)), but many VPNs are blocked too. Other torrent addons, such as Comet, MediaFusion, StremThru Torz and the built-in ones, cover the same ground.

  </Accordion>

  <Accordion title="Fewer or different results than on a public instance">
    Public instances point addons such as Comet, MediaFusion and StremThru Torz at their own copies, or at ones they trust. Your instance uses each addon's default address, which may be slower or find less. Set the address you want for each addon in the dashboard's **Settings** (for example **Comet › URL**, `COMET_URL`), or in the addon's own settings on the configure page.

  </Accordion>

  <Accordion title="Streams buffer through my domain but not on the local address">
    Proxied streams (from the built-in proxy or the Usenet engine) pass through your server, so everything between it and your player counts:

    - **Cloudflare's proxy and tunnels** aren't made for video and slow down or cut long streams. Serve AIOStreams without them.
    - **Tailscale Funnel** relays everything through Tailscale's servers. A direct Tailscale connection between your devices doesn't.
    - **The server's own connection.** Copy a stream's link (it contains `/api/v1/proxy`) and download it in a browser to see the speed you actually get.

  </Accordion>

  <Accordion title="Signing in to a configuration fails behind a reverse proxy">
    The configure page sends your UUID and password in an `Authorization` header. If the error says the header is missing, something between the browser and AIOStreams removed it: a proxy rule, an http-to-https redirect on a different address, or a stale cached copy of the page. Compare both routes:

    ```sh
    curl -i -u 'UUID:PASSWORD' 'https://your-domain/api/v1/user?raw=true'
    curl -i -u 'UUID:PASSWORD' 'http://<container-ip>:3000/api/v1/user?raw=true'
    ```

    If the second works and the first doesn't, the proxy is the cause. The dashboard signs in with a cookie instead, so it can work while this fails.

  </Accordion>

  <Accordion title="TMDB calls fail in India">
    `api.themoviedb.org` is blocked in India, which affects VPS regions there such as Oracle Cloud's. Send TMDB calls through a proxy, such as WARP:

    1. Add the proxy under **Addon proxy URL(s)** in the dashboard's **Settings** (`ADDON_PROXY`).
    2. Route TMDB through it with `api.themoviedb.org:true` in **Addon proxy config** (`ADDON_PROXY_CONFIG`).

  </Accordion>

  <Accordion title="The configure page is blank or errors on load">
    Check the container logs first:

    ```sh
    docker compose logs -f aiostreams
    ```

    Common causes:

    - **A port conflict.** Another service uses the same port: change the host port in `compose.yaml`.
    - **`BASE_URL` doesn't match.** It must be the address your browser uses, with `https://` and no trailing slash.
    - **A cached old version.** After an update, reload the page without the cache (Ctrl+Shift+R), and clear your proxy's cache if it has one.

  </Accordion>
</Accordions>

## Still stuck?

Join the [Discord server](https://discord.viren070.me) and ask in `#support`. Say which instance you use (or that you self-host), what you expected and what happened, and include any error message. Self-hosters, add the logs, from the dashboard's **Logs** page or `docker compose logs aiostreams`.
