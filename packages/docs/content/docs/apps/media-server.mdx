Every configuration is also a **media server**. The [AIOStreams app](/apps), in a browser or on your computer, phone, tablet or TV, signs in to it, and so does any [Jellyfin app](/apps/jellyfin), because the server speaks the same API as Jellyfin. You don't need to install or host anything for it: it runs on your AIOStreams instance. Public instances have it on except ElfHosted's, and ElfHosted's private instances have it off until you turn it on. Nothing is downloaded or stored either: when you press play, AIOStreams searches your addons exactly as it does for Stremio.

| In AIOStreams                     | In the apps                                             |
| --------------------------------- | ------------------------------------------------------- |
| Your catalogs                     | Libraries                                               |
| Your metadata addons              | Titles, with their details, seasons and episodes        |
| The streams found for a title     | Versions of that title                                  |
| Your subtitle addons              | Subtitle tracks                                         |
| Catalogs of collections           | A Collections library                                   |
| What you watch, and your trackers | Continue Watching, Next Up, played marks and favourites |

Its settings are on the configure page: addresses, Quick Connect, versions and skip markers under **AIOStreams app → Setup**, and the people who watch under **AIOStreams app → Profiles**.

## Before you start

- **Use streams with a link.** Only streams with a URL play in the apps: debrid, Usenet and direct links. P2P torrents, which Stremio plays through its own torrent engine, are left out.
- **Add catalog and metadata addons to AIOStreams.** The apps only see what your configuration provides, so they need addons for all three jobs: catalogs to fill the libraries, metadata to describe each title, and streams to play it.
- **Save your configuration.** The apps sign in to a saved configuration.
- **Check the instance allows it.** It is on by default. If the buttons under **AIOStreams app → Setup** are greyed out, the instance owner has turned it off.

<Callout type="info">
  Streams are **played directly**, never transcoded. Your app has to be able to
  play the file as it is, so a device that struggles with a format in other apps
  will struggle here too. Picking another version usually helps.
</Callout>

## Profiles and PINs

**AIOStreams app → Profiles** adds profiles to your server, so everyone in a household can have their own, with their own Continue Watching, trackers and addon setup.

- **The owner** is your configuration itself. Give it a name (your addon name by default), an avatar and, optionally, a [PIN](#the-owners-pin). You can hide it from the sign-in picker; it still signs in by typing its name.
- **Each other profile** has a name, which is also what they type to sign in by hand, and an optional avatar. A profile can be [kept separate](#profiles-outside-your-household) from the others.
- **Order** is the order apps list them in on the [sign-in picker](/apps/jellyfin#connecting-an-app): drag a profile's row to move it up or down. The owner is always first.
- **History** is either **own**, a separate Continue Watching, or **shared** with the owner. Sharing the history also shares its trackers.
- **Variants** apply while that profile is signed in, in the order picked, so a profile can get, for example, a different set of filters. A variant that activates on its own applies too, [before the ones picked here](/reference/config-expressions#what-applies-in-what-order).
- **Addons and catalogs** can differ per profile without writing a variant: the people button beside each one in **My Addons** and **Catalogs** chooses [who gets it](/reference/config-expressions#who-gets-an-addon-or-catalog).
- **Trackers** can be chosen per profile; see [Trackers for each profile](#trackers-for-each-profile).
- **App settings**, such as languages and the home page, can be set for each profile and as defaults for everyone; see [Settings](/apps#settings).
- **PIN** is optional; see below.

Removing a profile keeps their watch history. Adding a profile again under the same name gets it back. Their own choices of addons and catalogs go with them.

### PINs

Give a profile a PIN of 4 to 12 digits to stop others in the household signing in as them. PINs are an AIOStreams addition, so [Jellyfin apps](/apps/jellyfin) have no box for one: type it in the password box after the password, as `yourpassword/1234`. Without it, an app only reports a failed sign-in. The AIOStreams app is the exception and asks for the PIN on its own, both at sign-in and when switching to that profile. Quick Connect asks for it before approving. API keys can't act as a profile with a PIN.

- Five wrong PINs in a row pause sign-in to that profile for 15 minutes.
- Changing or removing a profile's PIN signs that profile out on every device.
- The owner can still see a PIN profile's watch history, but can't mark things watched as them.

### The owner's PIN

The owner sees everyone's activity and history, so a PIN on it keeps the other people using your configuration out of yours. With one set:

- Signing in as the owner always needs the PIN, even with your configuration password.
- Switching to the owner from another profile in the AIOStreams app asks for the PIN every time, so handing over a device after switching away doesn't hand over your account.

### Letting people sign in with only their PIN

Sometimes the people you set up profiles for shouldn't know your configuration password, because it also opens the configure page. If the instance owner allows it, each of them can sign in with their own PIN instead. **Connect**, under **AIOStreams app → Setup**, says whether your instance does.

1. Give each person's profile a PIN of **6 or more digits**.
2. Give them the [**Address with a sign-in picker**](/apps/jellyfin#connecting-an-app), their profile name and their PIN.
3. They pick their profile and enter the PIN as the password.

This only works on the sign-in picker address or a [separate profile's own address](#profiles-outside-your-household), and only for profiles other than the owner. The owner, and profiles without a PIN, still need your configuration password, and a PIN shorter than 6 digits only works together with it. Anyone with the picker address or your install links who learns or guesses a PIN can sign in as that profile, so pick PINs that aren't easy to guess.

### Profiles outside your household

To share your setup with someone who shouldn't see your household, turn on **Keep separate from other profiles** in their profile's settings. A separate profile:

- is left off the sign-in picker and every other profile's list;
- sees no other profile once signed in, and can't switch to anyone;
- gets an address of their own, shown under the switch with a **Copy** button: `https://your-instance/jellyfin/p/<code>`.

Give them only that address. It signs in that one profile, doesn't show your other profiles, and has no secret in it, unlike the picker address and your install links. They sign in with their PIN if the instance [allows PIN-only sign-in](#letting-people-sign-in-with-only-their-pin); otherwise approve each of their devices with [Quick Connect](/apps/jellyfin#on-a-tv-quick-connect). The address starts working once you save, and **New address** replaces it, so a leaked one stops working.

Give a separate profile their own history. A profile that shares the owner's history also sees its Continue Watching.

### Switching profiles

In the [AIOStreams app](/apps), select your avatar to switch profiles without signing out:

- Switching to a profile with a PIN asks for their PIN.
- Once in, a profile with a PIN stays unlocked on that device, even after the app restarts, until they switch away or sign out. Going to the profile picker counts as switching away, so switch away before handing the device to someone else.
- A device that signed in with your configuration password switches to profiles without a PIN freely.
- A device that never had your password, because it was approved with Quick Connect or signed in with a PIN alone, asks for the password to reach the owner or any profile without a PIN. For an owner with a PIN, it asks for both, as `yourpassword/PIN`.

### Signing devices out

- **One profile, everywhere:** change or remove their PIN.
- **Everyone, everywhere:** change your configuration password. That also changes the picker address and your Stremio install links and stops every [API key](#api-keys), so hand out the new ones afterwards.

<Callout type="info">
  A PIN keeps other people using your addresses out of that profile. It does not
  protect against anyone who can open your configuration, who can change or
  remove it. For people who need to be fully separate, use separate
  configurations.
</Callout>

## Libraries

Each catalog becomes a library, in the order set on the **Catalogs** page. Reorder or disable catalogs there to change what apps show.

- **Limits.** An instance shows a limited number of libraries per configuration (500 at most, and by default) and lists a limited number of titles in each (250 by default). **Connect**, under **AIOStreams app → Setup**, tells you this instance's numbers. Catalogs past the library limit do not appear at all, so move the ones you care about to the top.
- **Search.** Searching in an app searches your catalogs that support search. Search-only catalogs are not shown as libraries.
- **Genres.** A catalog with genres gets a genre filter. A catalog that requires a genre opens on its first one.
- **Collections.** A catalog whose entries are collections, such as a set of streaming services or film series, becomes a **Collections** library. A collection can hold both movies and shows, and each opens and plays like it does anywhere else.

Changes you save reach connected apps within about 30 seconds. Apps also keep their own copy for a while, so refresh or reopen the app if something still looks old.

## Playing

### Versions

Opening a movie or an episode searches your addons, just as opening it in Stremio does, and lists the results as **versions**. Their names come from your [formatter](/reference/custom-formatter). The first version is the one your sorting ranks highest, so pressing play without choosing picks the same stream Stremio would put at the top.

Two settings under **Jellyfin apps**, on **AIOStreams app → Setup**, control this:

| Setting                                | What it does                                                                                                                                                                                                                       |
| -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Resolve streams when an item opens** | On by default. Off, nothing is searched until you press play or an app asks for the version list, which is lighter on your addons, but the version list shows a placeholder until then, with a **Load versions** entry to fill it. |
| **Versions per item**                  | How many streams Jellyfin apps get, up to the instance's maximum (25 by default). At 1, they have nothing to choose between. The AIOStreams app gets up to 500 by default; **Results → Limits** caps those.                        |

A title's versions are reused for a few minutes, so opening it and then playing it searches once.

Anything an addon sent with nothing to play, such as a notice, an error, or a link to its own website, is listed after the versions, along with any statistics you have switched on. Stremio offers these as links to open in a browser, which a Jellyfin app has no way to do, so only their text is any use there, and playing one gets you a short clip saying so. The [AIOStreams app](/apps) shows them as text too, with a button to open any link. They do not count towards **Versions per item**, and errors follow your **Hide Errors** setting.

### Audio and subtitle tracks

Subtitles from your subtitle addons show up as subtitle tracks in every app. The file's own audio and subtitle tracks depend on what AIOStreams knows about the stream:

- **Media info that lists the tracks:** every track, named as in the file.
- **Only the languages**, as some addons and indexers report: one numbered track per language, such as **Audio 2** or **Subtitle 1**. A file with two tracks in one language has one more than is listed.
- **Nothing:** one audio track and none of the file's subtitles.

Unless the instance owner has turned it off, AIOStreams reads a file's tracks the first time it plays through the built-in usenet service, TorBox, or a proxy set up under **Proxy** on the configure page, and remembers them for everyone on the instance. Debrid files played any other way are never read, since that could add an IP to the account. From the next play on, that version lists every track.

To get every track on the first play too, set **Wait for tracks on play** under **Jellyfin apps**. Playing a version whose tracks aren't known yet then waits for them, for up to that many seconds. Some apps give up after about 20 seconds, so stay below that. The setting only shows when the instance reads files on play and your configuration plays something it can read.

Apps that read the tracks from the file themselves, and the [desktop](/apps/desktop) and [Android](/apps/android) apps, list every track regardless.

The tracks a version starts on follow each profile's audio and subtitle languages and subtitle types, set in the AIOStreams app under **Settings → Audio** and **Settings → Subtitles**, or everyone's where the profile hasn't set its own, so Jellyfin apps start on the same tracks.

### When nothing plays

- **No streams found** is shown when your addons returned nothing playable and none of them reported why. When one did, its error is listed in place of it, the same message Stremio would show. Either is looked up again after a few minutes.
- **Some streams never appear as versions.** P2P torrents have no link to play, so they are always left out. A stream that needs custom request headers can only be played in an app through a proxy, set up under **Proxy** on the configure page, so without one it is left out.
- **A version will not start.** Try another version. Because nothing is transcoded, a file your device cannot decode will not play.

### Skipping intros and credits

Unless the instance owner has turned it off, **Skip markers**, on **AIOStreams app → Setup**, has **Skip intro and credits**, on by default. Apps then get markers they can show a skip button for, and you can choose which markers to offer: intro, recap and credits. Whether the app skips automatically or asks first is a setting inside the app. The markers come from community databases, so on a differently cut copy of an episode they can be a few seconds out.

### Playing on another device

Apps signed in to your configuration can send each other titles and work as each other's remote, as Jellyfin apps do with their **Play on** or cast menu. Each profile controls the devices signed in as themselves, and the owner controls everyone's. A device only shows up while its app is open.

### Playlists

Each profile's playlists are kept on your instance, so the AIOStreams app and every Jellyfin app share them, and once a profile has one, Jellyfin apps also show a **Playlists** library. A playlist holds up to 1,000 titles, each once, and a profile can have up to 200. Adding a show adds its episodes that have aired.

## Watch history

AIOStreams keeps your progress, played marks and favourites itself, for your configuration and for each profile with its own history. That is what fills **Continue Watching** and **Next Up**, and it is the same on every app you sign in to.

### Trackers

An addon that supports **Watch State** can act as a tracker. **Trackers**, under **AIOStreams app → Profiles**, lists the ones in your configuration and what each does:

- **Records your plays**: what you watch in the apps is sent to the addon, so a service it connects to (such as a watch-history site) stays up to date.
- **Imports your history**: what the addon knows you watched elsewhere, including in Stremio, shows up in Continue Watching and Next Up.
- If the addon supports a watchlist, your watchlist and your favourites stay in step.

To stop an addon syncing for everyone, untick **Watch State** in that addon's **Resources** option and save. The instance owner can turn either direction off for everyone, in which case the page says so.

<Callout type="info">
  Without a tracker, AIOStreams only knows what you played in the apps.
  Something watched in Stremio reaches Continue Watching only through a tracker
  that imports your history.
</Callout>

Building a tracker addon? See the [Watch State reference](/reference/addon-protocol/watch-state).

### Trackers for each profile

Each profile with a history of its own can sync with its own tracker addons, for example a separate watch-history account per person. Add one tracker addon per account to your configuration, then turn on **Choose trackers** for each profile under **AIOStreams app → Profiles** and pick theirs.

- A tracker belongs to one history at a time, so a tracker picked for one profile can't be picked for another. Otherwise what one person watches would end up in the other's history.
- The exception is a tracker addon that keeps profiles apart itself, such as one with a card per person. It can be picked for every profile, and AIOStreams tells it which profile each play is for. The addon matches a profile by name; when **AIOStreams app → Profiles** shows a **tracker id** for someone, give the addon that id as well.
- Left off, the owner syncs with every tracker addon, so none are free for other profiles. Choose the owner's trackers first.
- Left off for another profile, it syncs with a tracker addon that its variants add, and with any tracker addon that keeps profiles apart.
- A tracker nobody picks is not used.
- Moving a tracker to another profile also brings along what it already recorded for the previous one.

## Different addons for the apps and Stremio

Stremio and the apps read the same configuration, so an addon you add for one shows up in the other. Some addons only make sense in one of them: a metadata addon with catalogs built to be libraries, say, or one you already install in Stremio on its own. **Who gets this** keeps them apart.

<Steps>

<Step>

### Set it up for the apps

Add the addon, then order and enable its catalogs on the **Catalogs** page for the libraries you want.

</Step>

<Step>

### Keep it out of Stremio

In **My Addons**, click the people button beside the addon to open **Who gets this**. Turn off **Base config**, which is what a Stremio install link without a variant gets, and leave on the profiles who should have it. Then save.

</Step>

</Steps>

Stremio needs nothing new: its install link stays the same. The addon's catalogs stay on the configure page while any profile has it, and each catalog in **Catalogs** has the same button, for a catalog only the apps should show. If you install Stremio from a variant's link, turn that variant off instead of **Base config**.

**Who gets this** writes [variant](/reference/config-expressions) lines for you; [who gets an addon or catalog](/reference/config-expressions#who-gets-an-addon-or-catalog) explains them. Two other ways to do it:

- **A variant of your own**, for anything else that should differ in Stremio, such as its addon name. In **Advanced → Variants** (Advanced mode), add a variant with the id `stremio`, with lines such as `disable presets[instanceId=8ae]` (the editor completes instance ids and names each addon) or `set addonName = "..."`. Then pick the `stremio` variant on the **Stremio** page and install from there; its install links end in `/v/stremio`.
- **A separate configuration**, when the two setups share little. Create a second configuration for the apps and sign in to that one instead. See [variants or a parent config](/reference/config-expressions#variants-or-a-parent-config) for how the two approaches compare.

## API keys

A tool that uses the Jellyfin API, such as a dashboard or a script, can connect with an API key instead of your password. Open **API keys** at the bottom of **Connect**, under **AIOStreams app → Setup**:

1. Name the key and select **Create key**.
2. Save your configuration.
3. Select **Copy key**, and give it to the tool with the same server address your apps use.

A key acts as the server's administrator, though it can't act as a profile with a [PIN](#pins). It sees every profile of your configuration: what each is watching now, their watch history, and your libraries. Revoke a key and save to cut a tool off; it stops working within 30 seconds. Changing your configuration password stops every key, so copy them again afterwards.

What a tool can't get from AIOStreams:

- **Addresses and locations.** AIOStreams does not record where anyone watches from, so rules built on IP addresses, such as account-sharing detection, have nothing to go on.
- **Stopping a stream or sending a message.** Apps can't be controlled remotely.
- **Transcoding and quality details.** Everything plays directly, and the stream details are not reported.
- **Every title.** Each library lists at most `JELLYFIN_MAX_CATALOG_ITEMS` titles, and episodes are listed per show, not per library.

## For instance owners

The media server, skip markers and watch-state sync are on by default. The settings are under **Dashboard → Settings → Media server** and **Watch State**; see [environment variables](/configuration/environment-variables) for all of them.

| Variable                         | Default    | What it does                                                                                                             |
| -------------------------------- | ---------- | ------------------------------------------------------------------------------------------------------------------------ |
| `JELLYFIN_ENABLED`               | `true`     | Turns the media server on or off, for the AIOStreams app and Jellyfin apps.                                              |
| `JELLYFIN_MAX_LIBRARIES`         | `20`       | Catalogs shown as libraries per configuration. `0` shows them all.                                                       |
| `JELLYFIN_MAX_CATALOG_ITEMS`     | `250`      | Titles listed per library.                                                                                               |
| `JELLYFIN_MAX_VERSIONS`          | `25`       | The most versions a configuration can offer Jellyfin apps.                                                               |
| `JELLYFIN_MAX_APP_VERSIONS`      | `500`      | The most versions the AIOStreams app lists, whatever a configuration's own limit.                                        |
| `JELLYFIN_RESOLVE_ON_OPEN`       | `user`     | `always` or `never` force resolving on open for everyone; `user` leaves it to each configuration.                        |
| `JELLYFIN_MAX_PERSONAS`          | `20`       | Profiles per configuration besides the owner. `0` allows none.                                                           |
| `JELLYFIN_PIN_SIGN_IN`           | `false`    | Lets a profile with a PIN of 6 or more digits sign in on the picker address with the PIN alone.                          |
| `JELLYFIN_SEGMENTS_ENABLED`      | `true`     | Offers skip markers. It sends what is being played to the marker databases.                                              |
| `JELLYFIN_SEARCH_SUGGESTIONS`    | `cinemeta` | Where [search suggestions](#search-suggestions) come from: `cinemeta`, `lumieredb` or `catalogs`.                        |
| `JELLYFIN_LUMIEREDB_URL`         |            | The LumiereDB instance for `lumieredb` suggestions.                                                                      |
| `WATCH_STATE_REPORT_ENABLED`     | `true`     | Sends plays to tracker addons.                                                                                           |
| `WATCH_STATE_PULL_ENABLED`       | `true`     | Imports history from tracker addons.                                                                                     |
| `WATCH_STATE_MIN_RESUME_PERCENT` | `0`        | Stopping before this much has played keeps no resume point.                                                              |
| `WATCH_STATE_PLAYED_PERCENT`     | `90`       | Playing this much marks a title played.                                                                                  |
| `ALLOW_PRIVATE_URLS`             | `true`     | Lets this server reach private addresses, such as a tracker addon on a Docker network. Turn it off on a public instance. |

### Search suggestions

While someone types a search, the AIOStreams app suggests titles under the search box, and Jellyfin apps that show search hints get the same titles. **Search suggestions** (`JELLYFIN_SEARCH_SUGGESTIONS`) decides where they come from:

| Value       | Where suggestions come from                                                                                                                                                         |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `cinemeta`  | Cinemeta's list of about 20,000 popular movies and series, matched by their English names. The server downloads it the first time someone searches and keeps it in memory.          |
| `lumieredb` | A LumiereDB instance, which knows every IMDb title, copes with typos and finds titles by their original names too. Set its address in **LumiereDB URL** (`JELLYFIN_LUMIEREDB_URL`). |
| `catalogs`  | Each configuration's own catalog search, which knows what its addons do but costs as much as a full search.                                                                         |

LumiereDB is a self-hosted index of IMDb's datasets. Add it to the same compose file as AIOStreams, so AIOStreams reaches it by its container name:

```yaml
services:
  lumiere-db:
    image: ghcr.io/0xconstant1/lumiere-db:latest
    container_name: lumiere-db
    restart: unless-stopped
    user: '${PUID}:${PGID}'
    stop_grace_period: 75s
    expose:
      - 8000
    environment:
      - CACHE_MAX_BYTES=256MB
      - SUGGEST_ENABLED=true
    volumes:
      - ${DOCKER_DATA_DIR}/lumiere-db:/data
```

Create the data folder as your own user before the first start, or Docker creates it as root and LumiereDB can't write to it. The first start downloads about 2 GB from IMDb and builds its index, which takes a while, and it needs about 5 GB of disk. Then set **LumiereDB URL** to `http://lumiere-db:8000` and **Search suggestions** to `lumieredb`. Until LumiereDB URL is set, `lumieredb` suggestions come from Cinemeta. IMDb's datasets are for personal, non-commercial use.
