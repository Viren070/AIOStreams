The web app's **Theme** settings, under **Settings → Theme**, change its look for you on every device you sign in on. Each user of a server has their own.

- **Presets** set an accent and a background colour together.
- **Accent** colours buttons, progress bars and highlights.
- **Background** colours pages and panels, which take their shades from it. Dark colours read best.
- **Custom CSS** goes on top of the theme, for anything the colours don't cover.

## Adding custom CSS

Write your CSS in the **Custom CSS** box and press **Apply CSS**. A message then asks whether to keep it: press **Keep**, or it is undone after 15 seconds. That way CSS that hides the page, or the button, can't lock you out. Your text stays in the box either way, so you can fix it and try again.

Once kept, it is saved to your account and applies on every device you sign in on. It doesn't apply on the sign-in screens, since nobody is signed in there yet.

<Callout type="tip">
  If your CSS ever breaks the app on some device, add `?safe` to the address
  (for example `https://example.com/web/?safe`). Custom CSS stays off for that
  visit, so you can fix or clear it in the settings.
</Callout>

## A server's own CSS

A server's owner can style the app for everyone signed in to it, with **App custom CSS** in the dashboard's Branding settings, or `APP_CUSTOM_CSS`. It applies on the sign-in screens too, and before everyone's own custom CSS, so yours still wins. To leave it out for yourself, turn off **Use this server's CSS** under **Settings → Theme**. `?safe` turns it off for that visit as well.

## Finding what to style

Parts of the app carry a `data-ui` attribute naming what they are, and other `data-*` attributes saying which one or what state it's in. Aim your CSS at these rather than at class names, which change between versions.

To find a part's name, right-click it in a browser and choose **Inspect**, then look at the `data-ui` on it or on the elements around it. The [reference](#selectors) below lists them all.

```css
/* Every progress bar */
[data-ui='progress-bar-fill'] {
  background: hotpink;
}

/* Only those in the continue watching row */
[data-row='resume'] [data-ui='progress-bar-fill'] {
  background: hotpink;
}
```

## Examples

### True black

The **Background** setting does this best, since panels take their shades from it. With CSS:

```css
:root {
  --background: #000;
  --paper: #000;
  --color-gray-950: 0 0 0;
  --color-gray-900: 10 10 10;
}
```

### Squarer corners

```css
[data-ui='poster-card-image'],
[data-ui='wide-card-image'],
[data-ui='episode-image'] {
  border-radius: 0.25rem;
}
```

### Dim what you've watched

```css
:is([data-ui='poster-card'], [data-ui='wide-card'])[data-watched]
  [data-ui='artwork'] {
  opacity: 0.4;
}
```

### No zoom on hover

```css
[data-ui='poster-card']:is(:hover, :focus-visible) [data-ui='artwork'],
[data-ui='wide-card']:hover [data-ui='artwork'],
[data-ui='wide-card'] :focus-visible [data-ui='artwork'] {
  transform: none;
}
```

### Bigger posters in rows

```css
[data-ui='media-row'][data-shape='poster'] [data-ui='media-row-item'] {
  flex-basis: 14rem;
}
```

### Hide a row on the home page

```css
[data-row='upcoming'] {
  display: none;
}
```

A catalog's row is named `view:` and then its id. To find the id, open the catalog by clicking the row's title: the id is the part of the address after `/discover/`.

```css
[data-row='view:abc123'] {
  display: none;
}
```

To hide the featured banner, set **Featured on home** to **Nothing** under **Settings → Interface** instead.

### Hide what a catalog holds

A catalog's row on the home page says what it holds, such as **Shows** or **Movies**, beside its title.

```css
[data-ui='media-row'][data-row^='view:'] [data-ui='media-row-title'] a > span {
  display: none;
}
```

### Hide spoilers

Blur the pictures, titles and descriptions of episodes you haven't watched. Pointing at one fades it in.

```css
/* Episodes you haven't watched, until you point at one */
:is([data-ui='episode-card'], [data-ui='episode-list-item']):not(
    [data-watched],
    :hover,
    :focus-within
  )
  [data-ui='artwork'] {
  filter: blur(12px);
}
:is([data-ui='episode-card'], [data-ui='episode-list-item']):not(
    [data-watched],
    :hover,
    :focus-within
  )
  :is(
    [data-ui='episode-title'] > span,
    p[data-ui='episode-title'],
    [data-ui='episode-synopsis']
  ) {
  filter: blur(5px);
}

/* Next up and upcoming episodes, but not what you're partway through */
:is([data-row='next-up'], [data-row='upcoming'], [data-row='resume'])
  [data-ui='wide-card']:not([data-in-progress], :hover, :focus-within)
  [data-ui='artwork'] {
  filter: blur(12px);
}
:is([data-row='next-up'], [data-row='upcoming'], [data-row='resume'])
  [data-ui='wide-card']:not([data-in-progress], :hover, :focus-within)
  [data-ui='wide-card-subtitle'] {
  filter: blur(5px);
}

/* Fade the blur in and out */
[data-ui='artwork'] {
  transition-property: filter, transform, opacity;
}
[data-ui='episode-title'] > span,
p[data-ui='episode-title'],
[data-ui='episode-synopsis'],
[data-ui='wide-card-subtitle'] {
  transition: filter 0.3s;
}
```

Blur the text inside an episode's title rather than the title itself: the title is what makes the whole episode play when pressed, and a blur on it would shrink that to the title alone.

### Hide buttons on title pages

```css
[data-ui='item-action']:is([data-name='trailer'], [data-name='drop']) {
  display: none;
}
```

### Hide the score, and the dot before it

```css
[data-ui='item-meta'] [data-name='score'],
[data-ui='meta-separator']:has(+ [data-name='score']) {
  display: none;
}
```

### Square cast photos

```css
[data-ui='person-card-image'] {
  border-radius: 0.75rem;
}
```

### Versions

```css
/* Mark cached versions */
[data-ui='version'][data-cached] {
  border-color: rgb(var(--color-brand-500) / 0.6);
  background: rgb(var(--color-brand-500) / 0.08);
}

/* Ring the top version, since the list is sorted best first */
[data-ui='version']:nth-child(1 of [data-ui='version']) {
  box-shadow: 0 0 0 1px rgb(var(--color-brand-400));
}

/* Names in a fixed-width font, for formats laid out in columns */
[data-ui='version-name'],
[data-ui='version-description'] {
  font-family: ui-monospace, monospace;
}

/* A wider list on big screens */
[data-ui='dialog'][data-name='versions'] {
  max-width: 72rem;
}

/* Hide quick filters that find nothing for this title */
[data-ui='versions-quick-filter'][data-empty] {
  display: none;
}

/* Bigger badges */
[data-ui='version-badge'] {
  height: 1.75rem;
  font-size: 0.8125rem;
}
```

Leave choosing which versions appear to your filters, rather than hiding some with CSS. Hidden versions still count, and playing straight away or carrying on to the next episode can still pick them.

### The player

```css
/* A red timeline, thicker on hover */
[data-ui='seek-bar-progress'] {
  background: #e50914;
}
[data-ui='seek-bar-track'] {
  height: 6px;
}
[data-ui='seek-bar']:hover [data-ui='seek-bar-track'] {
  height: 10px;
}

/* Drop buttons you never use */
[data-ui='player-button']:is([data-name='speed'], [data-name='fit']) {
  display: none;
}

/* Bigger track lists, with the chosen one in the accent colour */
[data-ui='player-menu-item'] {
  font-size: 1.1rem;
}
[data-ui='player-menu-item'][data-selected] {
  color: rgb(var(--color-brand-300));
}
```

To change how subtitles look in a browser, style `video::cue`. The desktop and Android apps draw subtitles themselves, so use **Settings → Subtitles** there.

```css
video::cue {
  font-family: 'Trebuchet MS', sans-serif;
}
```

### Your own font

`@import` has to come first in the box.

```css
@import url('https://fonts.googleapis.com/css2?family=Outfit:wght@400;600;700&display=swap');

body {
  font-family: 'Outfit', sans-serif;
}
```

### Your own logo

```css
[data-ui='brand-logo'] {
  content: url('https://example.com/logo.png');
}
```

### Hide the scrollbar

```css
html {
  scrollbar-width: none;
}
::-webkit-scrollbar {
  display: none;
}
```

### Messages in the bottom right

On a phone they stay at the top, where they span the screen.

```css
@media (min-width: 640px) {
  [data-sonner-toaster] {
    top: auto !important;
    bottom: 24px !important;
    left: auto !important;
    right: 24px !important;
    transform: none !important;
  }

  /* Each message sits at the bottom, with older ones stacked above */
  [data-sonner-toast] {
    top: auto !important;
    bottom: 0 !important;
    --lift: -1 !important;
    --lift-amount: calc(-1 * var(--gap)) !important;
  }
}
```

### No fade-ins

```css
[data-page],
[data-ui='media-row-item'] > div,
[data-ui='card-grid'] > div {
  opacity: 1 !important;
  transform: none !important;
  top: 0 !important;
}
```

### Only in one app

```css
/* A bigger timeline in the desktop app only */
html[data-host='desktop'] [data-ui='seek-bar-track'] {
  height: 8px;
}

/* No suggestions under the search box in the Android app on a TV */
html[data-host='android-app'][data-tv] [data-ui='search-suggestions'] {
  display: none;
}
```

## When a rule doesn't take

Your CSS comes after the app's own, so a rule as specific as the app's wins. When one doesn't:

- **Hover and focus styles** need the same state in your selector. The zoom on a hovered poster, for example, is only undone by `[data-ui='poster-card']:hover [data-ui='artwork']`.
- **Animations** set their styles on the element itself, which only `!important` beats. Fade-ins and the message popups are like this.
- **Class names** change between versions, so a rule aimed at one can stop working after an update. The `data-ui` names and the [shared component classes](#shared-components) are kept stable.

## What CSS can't change

- **Subtitles in the desktop and Android apps**, which the player draws. Use **Settings → Subtitles**.
- **The page while a video plays in the desktop app.** It has to stay see-through for the video beneath it, so custom CSS can't give it a background then.
- **The sign-in screens**, before anyone is signed in.

### Shared components

Menus, dialogs, buttons and form controls come from a shared set of components. Their parts carry a class named `UI-<Component>__<part>`, kept stable like the `data-ui` names:

| Class                                                                                | What it is                          |
| ------------------------------------------------------------------------------------ | ----------------------------------- |
| `.UI-Modal__content`, `__overlay`, `__header`, `__title`, `__description`, `__close` | A dialog box and its parts          |
| `.UI-DropdownMenu__root`, `__item`, `__label`, `__separator`                         | A menu                              |
| `.UI-ContextMenu__root`, `__item`, `__label`, `__separator`                          | A right-click menu                  |
| `.UI-Tooltip__root`, `.UI-Popover__root`, `.UI-HoverCard__root`                      | Tooltips and popups                 |
| `.UI-Button__root`, `.UI-IconButton__root`                                           | Buttons                             |
| `.UI-Badge__root`                                                                    | A small label, such as a genre      |
| `.UI-Input__root`, `.UI-Textarea__root`, `.UI-Select__root`, `.UI-Switch__root`      | Form controls                       |
| `.UI-Card__root`                                                                     | A panel                             |
| `.UI-VerticalMenu__item`                                                             | A sidebar item                      |
| `.UI-Carousel__item`                                                                 | A card's slot in a row              |
| `.UI-Skeleton__root`                                                                 | A placeholder while something loads |

A message that fills a page or a row, such as an error or an empty catalog, is `[data-luffy-error]`, with `[data-luffy-error-image]`, `[data-luffy-error-title]` and `[data-luffy-error-content]` for its parts.

The popup messages use `[data-sonner-toaster]` for their container and `[data-sonner-toast]` for each one, with `data-type` set to `success`, `error`, `warning` or `info`.

## Colours

The theme's colours are CSS variables, which you can set in your CSS as well. Those holding an `R G B` triple are used as `rgb(var(--color-brand-500))`, or `rgb(var(--color-brand-500) / 0.5)` to make them see-through.

| Variable                                              | What it is                                                   |
| ----------------------------------------------------- | ------------------------------------------------------------ |
| `--color-brand-50` to `--color-brand-950`             | The accent's shades, as `R G B`                              |
| `--color-gray-50` to `--color-gray-950`               | The background's shades, used by panels and text, as `R G B` |
| `--background`                                        | The page's colour                                            |
| `--paper`                                             | The colour of menus and dialogs                              |
| `--foreground`, `--muted`, `--muted-highlight`        | Text, dimmed text, and dimmed text on hover                  |
| `--border`, `--ring`                                  | Borders, and the ring around what has keyboard focus         |
| `--subtle`, `--subtle-highlight`                      | Faint fills, such as behind a hovered item                   |
| `--brand`                                             | Accent-coloured text                                         |
| `--radius`, `--radius-md`                             | Corner rounding of menus and inputs                          |
| `--red`, `--orange`, `--green`, `--blue` and the like | Named colours for text                                       |
